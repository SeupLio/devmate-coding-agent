# 电商服务商 AI 工作台：真实场景价值与评价指标

> 这份文档回答三个问题：**谁在用、什么时候用、凭什么说它有用**。
> 最后一节专门写「做不到什么」，因为不写边界的价值主张等于没有价值主张。

---

## 一、真实场景定位：它在工作流的哪一环

### 谁在用

**平台电商服务商（如快手电商服务商）的商家运营团队。**
典型团队结构：1 个组长 + 3~8 个运营，每人负责 50~300 家商家。

### 他们的日常（没有工具时）

| 环节 | 现状 | 痛点 |
|---|---|---|
| **挑商家** | 老运营凭记忆和 Excel 排序，新人不会挑 | 「先跟谁」全靠经验，**能力无法复制** |
| **写跟进记录** | 写成流水账（「已沟通，待跟进」） | 记录无法沉淀成数据，**下次还得重新问** |
| **诊断经营问题** | 靠个人经验判断「大概是转化不行」 | 结论不可复盘，**同一个商家两个人说法不同** |
| **发话术** | 复制模板改几个字 | 回复率低，且新人容易踩红线（承诺结果、索要账号） |
| **看平台规则** | 靠群通知和记忆 | 规则更新易漏，**违规成本高** |

### 用了之后（本模块覆盖的环节）

```
上游数据（店铺后台 / CRM 导出 CSV）
        │
        ▼
① 清洗      脏数据 → 可用数据（同义写法归一 / 异常值拦截 / 去重 / 留痕）
        │
        ▼
② 打标      7 维结构化标签（带判定口径 + 置信度 + 需复核标记）
        │
        ▼
③ 诊断      健康分 + 问题清单 + **按「影响÷难度」排序的行动建议**
        │
        ▼
④ 话术      基于「标签 + 诊断 + 知识库」生成，过 SOP 硬红线质检
        │
        ▼
⑤ 回流      运营修正错标 → 归因（误标/漏标）→ 规则迭代依据
        │
        ▼
   产出：**今日跟进清单**（谁先跟 + 跟他说什么）
```

**一句话定位**：把「老运营脑子里的判断」变成**可复制的规则 + 可度量的指标**，
让新人第一天就能打出一致性达标的标签、拿到有依据的跟进清单。

## 二、它到底替代了什么

| 替代对象 | 具体替代了什么 | 可度量性 |
|---|---|---|
| **老运营的经验判断** | 「先跟谁」从凭感觉变成按「影响÷难度」排序 | ✅ 排序质量 NDCG@K 可测 |
| **口头/群里的口径传递** | 7 维标签 + 每条带判定口径（criteria） | ✅ 一致性 Kappa 可测 |
| **模板话术** | 基于诊断结论 + 知识库检索生成，非凭空创作 | ✅ 结构合规率 / 违规率可测 |
| **人工翻 Excel 挑数据** | 导入即清洗，结构性问题（列错位）主动报警 | ✅ 数据质量四维可测 |
| **「错了就改，改完就忘」** | 纠错记录 → 归因 → 输出具体迭代方向 | ✅ 规则准确率趋势可测 |

## 三、评价指标：怎么证明它有用

指标分三层。**关键区分：哪些现在就能测，哪些必须接真实业务数据。**

### 3.1 能力指标（✅ 现在就能测，已实测）

这一层回答「工具本身做得好不好」，不依赖真实业务数据，用金标准 + 挑战集离线评测。

| 指标 | 口径 | 实测值 |
|---|---|---|
| **打标准确率**（宏 F1） | 与人工标注比对 | 回归集 **100%** ｜ 挑战集单标签 **100%** |
| **痛点识别 F1** | 多标签（可多选） | 挑战集 **60%**（受限于关键词规则，见 §4） |
| **口径可交接性**（Cohen's Kappa） | 规则 vs 人工的一致性 | **1.00**（Landis & Koch「极好」） |
| **优先名单质量** | P@3 / NDCG@5 | P@3 **100%** ｜ NDCG@5 **100%** |
| **数据质量四维** | 完整度 / 准确度 / 一致性 / 唯一性 | 脏样本实测：检出 2 异常值 + 1 重复 + 1 处列错位 |
| **话术结构合规率** | 5 项自动质检通过率 | 三变体均 **0% 违规率**，质量分 0.89~0.93 |
| **规则打标 LLM 成本** | 单条调用成本 | **0**（规则层不调 LLM） |

> ⚠️ **这些数字要正确解读**：回归集 100% 是「口径被锁定」的证据（回归测试），
> **不是**「真实准确率」。真实泛化能力看挑战集 —— 那里暴露了 3 处失败，
> 其中同义词类已修复，否定/时态/文本数字类属**已知能力边界**（§4）。
> 详见 `docs/ECOM-EVALUATION.md`。

### 3.2 效率指标（⚠️ 需接真实业务数据才能测）

这一层回答「省了多少人力」，需要在真实团队里跑一段时间。

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| **人均日跟进商家数** | 有效跟进条数 / 运营人数 / 工作日 | 直接对应人力成本 |
| **清单准备耗时** | 从拿到数据到产出跟进清单的分钟数 | 现状是「翻 Excel + 回忆」约 1~2 小时/天 |
| **新人上手周期** | 新运营能独立产出合格跟进的天数 | 现状依赖老带新，通常 2~4 周 |
| **标签复核率** | 被标记「需复核」的标签占比 | 反映规则置信度，越低越好 |

### 3.3 业务指标（⚠️ 需真实投放数据）

这一层回答「有没有带来业务结果」。**这一层本模块目前无法提供任何数字** —— 没有真实投放。

| 指标 | 定义 | 说明 |
|---|---|---|
| **北极星：有效跟进率** | 跟进后 7 天内产生有效响应（回复 / 加微 / 约谈）的商家占比 | 把「工具好不好用」与「业务结果」连起来 |
| **话术回复率** | 发出话术得到回复的比例 | 需 A/B 对比（用工具 vs 用模板） |
| **优先名单命中率** | 清单前 10 名里最终成交的比例 | 验证排序口径是否真的对 |
| **违规发生率** | 因话术违规被处罚的次数 | 合规收益，通常比效率收益更被管理层看重 |

### 3.4 指标设计上的三个刻意选择

1. **为什么用 Kappa 而不是只用准确率**：若 90% 的商家都该打 P2，一个「无脑全打 P2」的规则也有 90% 准确率。
   Kappa 扣掉了「随机也能猜对」的部分，才能回答「口径能不能交接」这个真正的问题。
2. **为什么用 NDCG@K 而不是只报分类准确率**：运营每天只跟得动 5~10 家，
   真正消费的是**清单的前几名**。把 P0 排第 1 位和排第 5 位，业务价值完全不同。
3. **为什么单列「数据质量四维」**：**打标的上限由数据质量决定**。
   若上游表 30% 的比率列是空的，打标准确率再高也没意义。把数据质量作为前置指标，
   才能区分「准确率低」是规则问题还是数据问题。

## 四、诚实边界：做不到什么

**这一节比前三节重要。** 不知道边界，就会在错误的场景用它。

| 边界 | 具体表现 | 为什么不在规则层解决 | 正解 |
|---|---|---|---|
| **否定句** | 「已经没有仅退款问题了」被误判为退款率高 | 关键词规则无法识别否定 | 接 LLM 兜底，或引入否定检测 |
| **时态/改善语义** | 「之前退款多，现在已经降下来了」被判为当前痛点 | 同上 | 同上 |
| **文本内数字** | 「客服响应要 120 秒」不触发「响应慢」 | 规则只读结构化字段 | 文本数值抽取（正则 + 上下文） |
| **不在体系内的类目** | 「宠物用品」归「其他」 | taxonomy 只有 5 个类目 | 按业务需要扩 taxonomy（不是 bug） |
| **无真实业务数据** | 所有业务指标（§3.3）都没有数字 | 本环境拿不到真实商家数据与投放数据 | 接入真实数据后补测 |
| **未接真实系统** | 数据靠 CSV 导入，不是直连数仓 / CRM | 无接口权限 | 接数仓 + CRM |

**这六条里，前三条是「能力边界」（要换技术方案），后三条是「落地缺口」（要接资源）。**
分清楚这两类，才知道下一步该投入什么。

## 五、要真正落地，还差什么（按优先级）

| 优先级 | 事项 | 为什么 |
|---|---|---|
| **P0** | 接真实商家数据（替换合成 demo 数据） | 所有业务指标都依赖它；也是校准阈值的前提 |
| **P0** | 话术效果回流（记录商家回复率） | 把「结构合规」升级为「真实效果」 |
| **P1** | 打标接 LLM 兜底（自由文本抽取） | 解决否定/时态/文本数字三类边界 |
| **P1** | 扩标注样本到 n≥100 后再校准阈值 | 当前 n=24 而参数 6 个，校准必然过拟合（已实测提升 0%） |
| **P1** | 直连数仓 / CRM，去掉 CSV 手工导入 | 效率指标的最大瓶颈 |
| **P2** | 竞品调研与业务访谈 | 验证指标口径是否符合业务真实关注点 |

## 六、一句话总结

> 这个模块的真实作用不是「用 AI 替代运营」，而是
> **把运营的判断力变成可复制、可度量、可迭代的资产** ——
> 让「先跟谁、跟他说什么」这件事从依赖个人经验，变成一套
> **有明确口径、有一致性指标、有纠错回流**的流程。
>
> 它的价值上限由**数据质量**决定，它的当前短板是**真实语言变体**（否定/时态），
> 这两点都已在 §4 写清楚 —— 而不是靠一个好看的准确率数字掩盖过去。
