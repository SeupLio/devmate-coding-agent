# 电商服务商工作台 · AI 能力 PRD（精简版）

> 本文档对应 JD 第 5 条「需求整理」与第 1 条「梳理 AI 可落地的业务机会」。
> 只写**决策**，不写实现细节 —— 实现见代码，业务口径见 `docs/ECOM-JD-ALIGNMENT.md`。

---

## 一、背景与问题

服务商（平台生态服务商）的一线运营同时跟进几十到上百个商家，日常痛点是：

| 痛点 | 现状 | 后果 |
|---|---|---|
| **不知道该先跟谁** | 靠记忆和感觉排序 | 高价值 + 高风险的商家被漏跟 |
| **诊断靠经验** | 每个运营自己判断「哪里有问题」 | 结论不一致，无法复盘，新人上手慢 |
| **话术靠模板** | 群发式模板，商家一看就知道 | 打开率低，专业感差 |
| **知识散落** | 平台规则/方法论/案例散在群聊和文档里 | 回答口径不一致，容易说错 |

**AI 的机会点**：这四件事的共同特征是「**有明确业务规则、但人工执行成本高**」——
正是 AI 该介入的地方。

---

## 二、目标与非目标

### 目标
1. 让一线运营**一眼看出**今天该先跟哪几个商家
2. 把「经营诊断」从个人经验变成**可复用、口径一致**的能力
3. 让跟进话术**有数据依据**，而不是通用模板
4. 把散落的业务知识变成**可检索**的知识库

### 非目标（本期不做）
- ❌ 不做自动发送（所有话术由人确认后手动发出）—— 涉及对外沟通，风险高
- ❌ 不做商家侧的 C 端产品
- ❌ 不替代运营的判断，只做**建议**（辅助决策，不是自动决策）

---

## 三、场景优先级（为什么先做这四个）

排序依据：**业务价值 × 落地难度**。

| 优先级 | 场景 | 业务价值 | 落地难度 | 判断 |
|---|---|---|---|---|
| **P0** | 数据打标（商家画像结构化） | 高 | **低** | 是其他场景的地基，先做 |
| **P0** | 经营诊断 + 任务推荐 | **高** | 中 | 最直接的效率提升，且规则明确 |
| **P1** | 业务知识库检索 | 中高 | **低** | 复用已有能力，成本低 |
| **P1** | 话术生成 | 中高 | 中 | 依赖前两项的产出 |
| **P2** | 线索跟进自动化 | 高 | **高** | 涉及对外沟通，需谨慎 |

**关键判断**：先做**打标**而不是先做话术。
因为话术的质量依赖「知道这个商家是什么情况」——
没有打标和诊断，话术就只能靠模型编。**先把上游数据做扎实，下游才不虚。**

## 四、各场景指标口径

### 4.1 数据打标

| 指标 | 口径 | 目标 |
|---|---|---|
| 打标覆盖率 | 该维度成功打标的商家数 / 总商家数 | ≥ 80% |
| 需复核率 | 置信度 < 0.7 的标签数 / 总标签数 | ≤ 20% |
| 标签一致性 | 同一商家重复打标结果一致率 | 100%（规则打标应确定性） |

### 4.2 经营诊断

**核心指标达标线**（来自《经营方法论》，可由运营调整）：

| 指标 | 健康线 | 预警线 |
|---|---|---|
| 支付转化率 | ≥ 2.5% | < 2% |
| 退款率 | ≤ 8% | > 10% |
| 客服响应时长 | ≤ 30s | > 60s |
| 月进店量 | ≥ 3000 | < 1000 |

| 指标 | 口径 | 目标 |
|---|---|---|
| 健康分 | 100 起扣，critical −25 / warning −10，最低 0 | —— |
| 诊断覆盖率 | 有 ≥2 项指标的商家占比 | ≥ 70% |
| 诊断采纳率 | 运营实际执行了推荐任务的商家占比 | 待真实数据 |

### 4.3 话术生成

| 指标 | 口径 | 目标 |
|---|---|---|
| 结构合规率 | 通过 5 项质检的话术占比 | ≥ 90% |
| 违规率 | 命中 SOP 禁止事项的话术占比 | **0%**（硬红线） |
| 商家回复率 | 商家实际回复的占比 | 待真实投放数据 |

> ⚠️ **诚实说明**：前三项可在本项目内计算；**「商家回复率」需要真实投放数据，本项目没有**。
> 这是「结构合规」与「真实效果」的差距，必须说清楚。

### 4.4 知识库

| 指标 | 口径 | 目标 |
|---|---|---|
| 检索命中率 | 查询能返回相关小节的占比 | ≥ 80% |
| 首条准确率 | 首条结果就是正确答案的占比 | ≥ 70% |

## 五、验收标准

| 场景 | 验收标准 |
|---|---|
| 数据打标 | 6 个典型商家样本上，标签与人工标注一致率 ≥ 90%；缺数据的商家不被硬打标 |
| 经营诊断 | 诊断结论能被运营理解并复述；推荐任务数量 ≤ 3 条；数据不足时明确提示 |
| 话术生成 | 违规率 0%；结构合规率 ≥ 90%；话术含该商家的**真实数据**而非泛泛而谈 |
| 知识库 | 4 组真实业务问题的首条命中率 100%（已达成，见对齐文档） |

## 六、三阶段迭代规划

### 阶段一（已完成）：能力地基
- 标签体系 + 打标引擎（规则优先、可解释、带置信度）
- 经营诊断 + 任务推荐（规则引擎、按影响/难度排序）
- 业务知识库（4 篇结构化文档 + RAG 检索）
- 话术生成 + 自动质检 + Prompt 变体对比器
- 前端「服务商工作台」面板（可交互原型）

### 阶段二（下一步）
- **补跑 Prompt 变体真实对比**（额度恢复后）
- **接入真实商家数据**替换合成数据
- 打标接入 LLM 兜底（覆盖口语化表达）
- 话术效果回流（记录商家回复率）

### 阶段三（探索）
- 线索跟进自动化（含人工确认环节）
- 竞品调研与业务访谈，校准指标口径
- 从「辅助建议」走向「半自动执行」

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| **话术说错话**（承诺平台做不到的事） | SOP 禁止事项做成**硬红线自动质检**，违规即拦截 |
| **诊断结论不可信** | 数据不足时**拒绝下结论**；结论必须带证据 |
| **运营不信任 AI 建议** | 每个标签/结论都可展开看依据；低置信度显式标注 |
| **数据质量差导致垃圾进垃圾出** | 在 SOP 里规定**跟进记录规范**（记事实、用明确词汇） |
| **AI 替代人的焦虑** | 定位为「辅助决策」而非「自动决策」；话术由人确认后发出 |
