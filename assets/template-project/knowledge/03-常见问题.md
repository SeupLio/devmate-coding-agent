# 常见问题（FAQ）

## 测试怎么跑？

```bash
node --test
```

Node 22 内置测试器，零依赖。不要引入 jest / vitest。

## 为什么不能改成 ESM？

下游有 CommonJS 消费者，改成 ESM 会破坏它们的 `require()`。
新增文件也用 `module.exports`。

## 测试失败了怎么办？

1. 先看失败断言的具体值，判断是**实现错了**还是**测试预期错了**。
2. 如果是实现错了 → 改实现。
3. 如果确认是测试预期过时 → **在提交信息里说明为什么改预期**，不要静默改。
4. **绝对不要**为了让测试通过而删除或注释掉断言。

## 遇到「未导出」导致的测试覆盖不到？

把符号加进 `module.exports`，然后补测试。不要用 `require('./mathutils').maxOf`
这种绕过导出的写法。

## 提交前要做什么？

1. `node --test` 全绿
2. 自评审一遍改动（有没有调试残留、有没有硬编码密钥）
3. 按 Conventional Commits 写提交信息（见《提交规范》）

## 代码风格

- 2 空格缩进，无分号结尾（与本仓库既有风格保持一致）
- 不要引入格式化工具，改动范围越小越好

## 我不确定某个约定怎么办？

先在 `knowledge/` 里查（用 search_knowledge 工具），查不到再问。
不要凭猜测改约定。
