# 架构说明

## 模块划分

```
mathutils.js        纯函数工具库（无副作用、无 IO）
mathutils.test.js   基于 node:test 的测试
knowledge/          团队文档（本目录），由 search_knowledge 工具检索
```

## 设计原则

### 1. 纯函数优先

`mathutils.js` 里所有导出函数必须是**纯函数**：相同输入必然得到相同输出，
不读全局状态、不写文件、不打日志。这样测试可以完全并行、无需 mock。

### 2. 输入校验放在边界

导出的公开函数**必须**校验入参类型。内部私有辅助函数可以不校验
（性能考虑），但公开 API 不行 —— 因为调用方可能是外部代码。

当前已知缺失：`sum` / `average` 对空数组、非数组输入没有防御。

### 3. 导出面最小化

只导出确实需要被外部使用的符号。历史上 `maxOf` 被实现但忘了导出，
导致测试无法覆盖 —— 这类「实现了但没导出」是常见的低级失误。

## 性能约定

- `fibonacci(n)` 必须支持 `n = 30` 且在 **1 秒内**返回。
  朴素递归实现（指数复杂度）不满足要求，需要改迭代或记忆化。
- 其余函数规模都很小，不设性能要求，优先保证可读性。

## 测试组织

- 一个源文件对应一个测试文件，命名 `<name>.test.js`。
- 断言要覆盖：正常路径、边界（空/0/负）、非法输入。
- **不要为了跑绿而删断言** —— 断言失败说明实现或预期有问题，要先搞清楚是哪个。
